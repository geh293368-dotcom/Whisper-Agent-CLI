# 产品体验、品牌与关于页规划

状态：部分实施；“听录 TINGLU”品牌、图标与关于页已接入，其他体验项仍在规划

记录日期：2026-06-11  

## 1. 当前产品定位

听录 TINGLU（工程名 `WhisperDesktop`）已经不再只是原始 WhisperDesktop 示例程序的界面替换。当前项目正在形成一套本地字幕工作台：

- whisper.cpp CPU 与 NVIDIA CUDA 转录。
- 批量文件和目录处理。
- SRT、VTT 和文本输出。
- WebView2、React 和 TypeScript 桌面界面。
- 后续计划加入本地大模型字幕后处理、RAG、术语库和虚拟领域画像。

因此，当前用户可见品牌已定为“听录 TINGLU”，使产品名称不再只表达“Whisper 的桌面外壳”，而是表达本地字幕生产和 AI 校正能力。

## 2. 当前性能观察

用户在实际批量任务中的主观观察：升级到新版 whisper.cpp CUDA 后，速度至少提升一倍，当前大致可在 1 分钟内处理约 1 小时媒体内容，即约 60x 实时速度。

该结果暂时作为产品观察记录，不能直接作为公开性能承诺。后续应使用 P1 已加入的批次统计记录：

- 媒体总时长。
- 实际处理耗时。
- 平均实时倍速。
- GPU、模型、量化版本和文件类型。

积累多组结果后，再决定 README 或发布页中的性能表述。

## 3. WebView2 桌面化

正式发行版应减少浏览器痕迹：

- 关闭默认右键菜单。
- 关闭开发者工具和“检查”。
- 关闭打印、刷新、查看源代码等浏览器命令入口。
- 关闭 Ctrl + 鼠标滚轮造成的意外缩放。
- Debug 构建可以保留开发工具，Release 构建默认关闭。

建议配置：

```csharp
settings.AreDefaultContextMenusEnabled = false;
settings.AreDevToolsEnabled = false;
settings.IsZoomControlEnabled = false;
```

## 4. 光标与文本选择

不建议粗暴地让所有区域永远显示箭头，也不建议禁止全局文字选择。字幕、日志、路径和错误信息仍然有复制价值。

推荐规则：

| 区域 | 光标 | 是否允许选择 |
| --- | --- | --- |
| 导航、标题、普通标签 | 默认箭头 | 否 |
| 按钮、链接、可点击卡片 | 手形 | 否 |
| 输入框和文本编辑区 | 文本光标 | 是 |
| 字幕预览、日志、文件路径 | 文本光标 | 是 |
| 表格列宽拖动位置 | 水平调整光标 | 否 |

这样既保留桌面软件的感觉，也不牺牲复制字幕和日志的能力。

## 5. 字号和界面缩放

当前界面大量使用 9px、10px 和 11px 字号，在高分辨率显示器上偏小。

建议建立统一设计变量：

```css
--font-caption: 11px;
--font-body: 13px;
--font-emphasis: 15px;
--font-title: 26px;
```

建议的设置选项：

- 紧凑：90%。
- 标准：100%。
- 较大：110%。
- 大字体：125%。

默认视觉大小可以在当前基础上提高约 10%。缩放设置保存在现有 `config.json`，但不能只使用浏览器整体 Zoom；优先通过 CSS 变量同步调整字号、行高、按钮高度和间距，避免布局失衡。

## 6. 生成式 UI 设计探索

可以使用 ChatGPT 图像生成或其他视觉工具探索新版界面，但生成图片只适合提供视觉方向，不应直接作为实现规格。

适合让图像模型探索的内容：

- 品牌色和整体气质。
- 首页、批量任务和 AI 校正页的布局方向。
- 关于页、空状态和模型加载状态。
- 图标、卡片、进度和统计信息的视觉层级。
- 深色模式与浅色模式。

图片方案落地前必须转换为明确的设计系统：

- 字号、间距和圆角。
- 颜色和对比度。
- hover、disabled、loading 和 error 状态。
- 最小窗口尺寸和高 DPI 行为。
- 大批量任务、长文件名和长日志等真实数据场景。

推荐一次生成 3 至 5 个不同方向，而不是只生成一张“漂亮界面”。评审后选定一个方向，再用 React 和 CSS 实现。

### 建议的图像设计提示词框架

```text
设计一款 Windows 本地 AI 字幕工作台的桌面应用界面。
核心功能包括批量视频队列、本地 CUDA 转录、字幕实时预览、日志、
视频总时长、处理速度和 ETA，以及后续 AI 字幕校正。
界面使用简体中文，信息密度适中，适合长时间专业工作。
不要做成网页营销页，不要使用夸张渐变或超大留白。
强调清晰表格、可读字号、文件层级、进度状态和桌面软件质感。
画布比例 16:10，目标窗口约 1380x860。
```

生成时可以分别追加以下风格方向：

- Windows 11 Fluent，克制、清晰、专业。
- 深色影视后期工作台，高信息密度。
- 现代 AI 工具，浅色、柔和、低饱和。
- 专业开发工具风格，强调队列和日志。

## 7. 关于页

关于页已实现，并通过左上角品牌区域进入，不在左侧导航占用单独菜单项。

交互方案：

- 点击左上角品牌图标或产品名称进入关于页。
- 再次点击或使用返回按钮回到上一个工作页。
- 保留键盘和无障碍访问方式，不只依赖图标。

关于页建议展示：

- 产品名称、图标和一句话定位。
- 当前版本、构建日期和 Git 提交号。
- 作者或维护者名称。
- 项目主页、GitHub、问题反馈和联系方式。
- 使用的核心开源项目及许可证入口。
- Whisper、whisper.cpp、WebView2、React 等第三方声明。
- 本地运行、隐私和数据不会上传的说明。
- 检查更新入口，后续实现。

作者链接已接入关于页；仍待补充的入口不应写死无效占位内容。

## 8. 产品改名评估

### 结论

已采用“听录 TINGLU”作为当前工作品牌；内部工程名和兼容路径继续保留 `WhisperDesktop`。

当前名称的问题：

- `WhisperDesktop` 容易被理解成 Whisper 的普通桌面封装。
- 难以体现批量字幕、CUDA、本地 AI 校正和术语记忆。
- 与历史项目名称、上游技术名称之间不容易建立独立产品识别。

### 推荐的改名层级

第一阶段只修改用户可见品牌：

- 产品显示名称。
- 左上角品牌文字。
- 窗口标题。
- About 页面和 README。
- 图标、发布包名称和安装程序名称。

暂时保留内部兼容名称：

- C# 命名空间 `WhisperDesktop.Modern`。
- 项目目录和解决方案结构。
- 配置目录 `%LOCALAPPDATA%\WhisperDesktop`。
- 日志目录和现有用户配置读取路径。

第二阶段在品牌稳定后，再决定是否迁移程序集、命名空间和仓库名称。配置目录迁移必须兼容旧数据，不能直接让用户丢失设置。

### 命名原则

新名称最好满足：

- 不把某一个模型名称写死，因为以后可能同时支持 Whisper、Gemma 和其他模型。
- 能表达字幕、语音、文本校正或本地 AI 工作流。
- 中文和英文都容易读写。
- 搜索结果中有一定区分度。
- 域名、GitHub 仓库名和常见软件商标需要正式确认。
- 不暗示与 OpenAI、Google、Microsoft 或上游项目存在官方关系。

品牌视觉可以继续使用，但在 Microsoft Store 正式提交前仍需完成名称预留、商标初筛、GitHub 与搜索冲突检查。当前不因品牌变更而大规模重命名代码。

## 9. .NET 10 升级

状态：已开始迁移现代 WPF 客户端与现代 UI 测试。

现代 WPF 客户端从 `.NET 9 / net9.0-windows` 迁移到 `.NET 10 / net10.0-windows`。这主要是运行时生命周期和维护周期升级，不会直接改善 React 界面、WebView2 右键菜单或 whisper.cpp CUDA 性能。

迁移范围：

- `Examples/WhisperDesktop.Wpf` 迁移到 `net10.0-windows`。
- `Tools/ModernUiTests` 迁移到 `net10.0`。
- 每日构建脚本更新到 `net10.0-windows` 输出路径，并声明需要 .NET 10 Desktop Runtime。
- `WhisperNet`、命令行示例、PowerShell 模块和旧工具暂不在本轮迁移，继续保留原有目标框架以降低兼容风险。

验证项：

1. `dotnet build Examples\WhisperDesktop.Wpf\WhisperDesktop.Wpf.csproj -c Release -p:Platform=x64`
2. `dotnet run --project Tools\ModernUiTests\ModernUiTests.csproj -c Release`
3. `Tools\package-daily.cmd`
4. 启动 `WhisperDesktop.Modern.exe` 做一次冒烟检查。
