## 总体判断

这四张图最有价值的是“信息架构”和“视觉统一方向”，不是里面每一个控件代表的功能。当前项目已经具备批量转写、实时字幕、模型加载、推理引擎切换、语言选择、本地/在线 AI Provider、AI 字幕优化、字幕输出策略、术语词库、日志和构建时间等状态。设计图中仍有一批功能目前没有真实后端或状态字段，例如自绘窗口标题栏、主题模式、自动语言检测、双语字幕、暂停恢复、显存占用、模型元数据、组件版本检测、说话人识别。

建议先做 P0：统一页面骨架、左侧导航、系统状态卡、底部状态条、卡片密度、按钮层级和图标风格。不要在 P0 引入没有宿主状态支撑的“假功能”。

## 统一视觉系统

### 推荐页面骨架

四个页面建议统一为：

1. 左侧深色导航栏：品牌区、主导航、次级入口、底部系统状态。
2. 右侧浅色内容区：页面标题、页面级操作、卡片/表格/状态模块。
3. 统一圆角：卡片 8-12px，主按钮 8px，图标容器 8px。
4. 统一信息层级：页面标题 > 模块标题 > 字段标签 > 状态说明。
5. 统一底部状态：批量和实时页面保留底部操作条，设置和关于页面可以不需要底部操作条。

### 黑白区域划分

设计图基本都是“深色侧栏 + 浅色工作区”。这是合适的，能把导航和任务面板分开，也符合桌面工具的使用习惯。需要注意：

- 深色区域只承担导航、品牌和系统状态，不放复杂表单。
- 浅色区域承担所有任务操作和数据表格。
- 不同页面不要有不同侧栏宽度、不同品牌文案或不同图标风格。
- 工作区背景保持浅灰，卡片保持白色，避免整个页面都是纯白导致层级不清。

## 标题栏决策

四张图对窗口标题栏不完全一致：

- 批量页和设置页更像浅色内容区顶部带最小化、最大化、关闭。
- 实时页和关于页更像深色系统标题栏。
- 当前 WPF 宿主仍使用默认 Windows 标题栏：`MainWindow.xaml` 没有 `WindowStyle=None` 或 `WindowChrome`。

### 方案 A：保留默认 Windows 标题栏

优点：

- 最稳，系统拖动、缩放、Alt+Tab、Snap Layout、DPI、无障碍都不需要重做。
- 不影响 WebView2 内部页面。
- P0 可以专注页面设计。

缺点：

- 和设计图的沉浸式窗口边框不完全一致。
- 页面顶部会显得没有 AI 图那种完整产品感。

建议：P0 采用。

### 方案 B：WPF 自绘标题栏

做法：

- WPF 设置 `WindowStyle=None` 或使用 `WindowChrome`。
- 在 WPF XAML 顶部放自定义标题栏，包含应用图标、标题、最小化、最大化、关闭按钮。
- WebView2 放在标题栏下方。
- 不建议完全由网页模拟拖动区域，因为 WebView2 不是 Electron，网页 CSS 不能直接获得原生拖拽窗口能力。

优点：

- 最接近设计图。
- 可以统一深色标题栏或浅色标题栏。

风险：

- 需要处理拖动、双击最大化、系统菜单、窗口缩放、DPI、Snap Layout、键盘焦点。
- 需要新增宿主窗口命令或 WPF 标题栏事件。
- 如果做得不完整，会比默认标题栏更难用。

建议：作为 P2 单独任务，不要混进页面重排。

## 左下角系统状态

最推荐采用“模型与设置”图的系统状态卡作为统一基准：

```text
系统状态：就绪/运行中/加载中/错误
GPU/引擎：CUDA / CPU / D3D11
模型：已加载 xxx / 尚未加载
AI：本地 qwen3:8b / Gemini 未配置
```

暂时不要在 P0 展示“显存 15.6/15.9GB”这类数据，除非 WPF 宿主已经能稳定采集。否则容易变成假状态。可以先显示已有的 `modelStatus`、`selectedEngine`、`selectedAiModelProvider`、`isRunning`、`isLiveRunning`、`isLoadingModel`。

## 图标生产建议

不建议直接从四张页面设计大图里抠所有图标。原因是页面图里的图标尺寸小、抗锯齿已经混入背景、同一概念在不同图里风格不一致，后续放到 16px 或 20px 按钮里会糊。

更好的路线：

1. 根据本文档冻结图标清单。
2. 用图像模型单独生成“透明背景图标板”，例如 2048x2048，8 列或 10 列网格。
3. 每个图标保持同一风格：蓝色主色、白色/浅蓝高光、线性或轻拟物不要混用。
4. 用脚本按网格裁切成 `png` 或 `webp`。
5. 应用 Logo 单独生成大尺寸版本，再导出 `ico`、`png`、窗口图标和侧栏图标。
6. 小尺寸工具图标仍建议保留 SVG 或图标字体备选，因为 16px raster 图标在高 DPI 下容易发虚。

## 声音提示需求

可以加，但建议做成可关闭的设置项，不要默认每个小步骤都响。

推荐触发点：

- 批量转写全部完成：轻提示音。
- AI 字幕优化全部完成：轻提示音。
- 实时字幕导出完成：轻提示音。
- 模型加载失败或批处理失败：错误提示音。

不推荐触发点：

- 每个文件完成都响。
- 每条实时字幕生成都响。
- 用户主动点击按钮后立刻响。

实现建议：

- P1 增加 `completionSoundEnabled` 设置，默认开启或默认关闭都可以讨论。
- WPF 侧可以先用系统声音，例如 `SystemSounds.Asterisk.Play()`；后续如果要品牌感，再放一个短 WAV 资源。
- 需要节流：同一批任务只响一次，失败时不要连续响。

## 不建议进入 P0 的内容

- 任务中心：当前批量队列已经承担任务中心职责。没有多任务后台队列、历史任务、下载/导出管理前，不建议新增导航项。
- 帮助与反馈：可以保留为后续入口，不建议先做页面。
- 显存占用：需要真实采集和刷新策略。
- 说话人识别：需要 diarization 能力，不是 UI 重排。
- 双语字幕：会影响字幕生成和导出格式，必须单独设计。
- 暂停恢复：需要批处理状态机支持，不是简单把“停止”按钮改成“暂停”。

## 推荐实施顺序

### P0：视觉统一，不扩功能

- 统一左侧导航和系统状态卡。
- 批量页改成设计图的“来源/任务队列/输出设置/预览/底部状态条”结构。
- 实时页改成“音频输入/会话信息/字幕表格/底部控制条”结构。
- 设置页按设计图重排已有设置项。
- 关于页保持当前产品卡 + 组件信息方向。
- 建立图标清单和临时图标占位规则。

### P1：低风险状态增强

- 模型文件大小显示。
- AI 连接测试详情。
- 优化试跑改成原始字幕/AI 优化后双栏预览。
- 任务完成提示音开关。
- 系统状态卡接入更多已有状态。
- 图标板生成和裁切。

### P2：真实新功能

- 自绘 WPF 标题栏。
- 主题模式。
- 自动语言检测。
- 双语字幕。
- 暂停/恢复。
- 显存/组件版本检测。
- 说话人识别。
