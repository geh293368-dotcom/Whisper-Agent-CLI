# 开发者诊断与字幕质量报告

## 目标

字幕评分、质量报告和 AI 优化对比主要服务开发者调试，不默认进入普通用户工作流。普通用户只需要知道字幕是否生成成功、是否需要优化、失败原因是什么；开发者需要看到评分、规则命中和批次质量趋势，用来改进模型选择、术语词库、断句策略和 AI 后处理。

## 第一版范围

当前版本只建立诊断模式的配置和界面入口，不接入 AI，不生成真实评分。

- 配置文件：`%LOCALAPPDATA%\WhisperDesktop\config.json`
- 配置项：`developerDiagnostics`
- 默认值：`false`
- 设置页入口：模型与设置 -> 开发者诊断
- 当前行为：保存开关、同步到前端状态、在日志中记录开关变化

## 用户层与开发者层

用户层默认保持简单：

- 生成成功、已跳过、失败
- 清楚的失败原因
- 必要时提示可以优化字幕
- 不展示分数、规则细节、质量报告

开发者层只在诊断模式中展示或生成：

- 批次质量摘要
- 单文件字幕评分
- 标点、断句、长句、空字幕、重复字幕统计
- 术语词库命中与纠错统计
- AI 优化前后对比
- 模型、文件大小、总时长、扫描耗时、转录耗时等上下文
- JSON / Markdown 报告

## 后续接入 AI 时的建议流程

1. 转写完成后收集字幕文本、时间轴、文件大小、媒体时长、模型、语言、术语词库状态。
2. 如果 `developerDiagnostics` 为 `false`，只保留普通用户结果，不生成诊断报告。
3. 如果 `developerDiagnostics` 为 `true`，运行质量评估规则。
4. 接入在线或本地大模型后，再补充 AI 评分、优化建议和优化前后对比。
5. 报告先写入输出目录或日志目录，不默认弹窗打扰用户。

## 报告草案

JSON 报告适合机器分析：

```json
{
  "fileName": "example.mp4",
  "durationSeconds": 3600,
  "fileSizeBytes": 2147483648,
  "score": 86,
  "issues": {
    "longSegments": 12,
    "missingPunctuation": 35,
    "emptySegments": 0,
    "duplicateSegments": 2
  },
  "terminology": {
    "enabled": true,
    "matchedTerms": 18,
    "corrections": 5
  },
  "aiOptimization": {
    "enabled": false,
    "provider": null,
    "model": null
  }
}
```

Markdown 报告适合人工查看：

```markdown
# 字幕质量报告

- 文件：example.mp4
- 评分：86
- 总时长：01:00:00
- 文件大小：2.0 GB
- 主要问题：长字幕 12 条，缺少标点 35 处，重复字幕 2 条
- 术语词库：命中 18 个术语，自动纠错 5 处
```

## 原则

- 不把诊断数据当成用户必须理解的结果。
- 不因为评分低就显示“生成失败”。
- 不默认上传字幕内容；在线 AI 接入必须有明确开关。
- 诊断报告优先帮助开发者改进软件，而不是给用户制造额外负担。
