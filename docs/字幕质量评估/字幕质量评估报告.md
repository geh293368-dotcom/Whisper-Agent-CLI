# 字幕质量评估报告

## 评估对象

本报告评估项目中 `00 Unity基础` 至 `10 九幽龙炎灭` 文件夹内的全部 SRT 字幕。

本次共检查：

- 79 个 SRT 文件。
- 约 326 万字节字幕数据。
- 54,114 个字幕时间单元。
- 课程内容涉及 Unity、Photoshop、3ds Max、粒子系统、材质、模型、UV、贴图和技能特效制作。

## 总体结论

当前字幕可以用于搜索课程内容、提取知识点和辅助 AI 总结，但还不适合作为直接交付给学员观看的成品字幕。

它更接近“语音识别过程的原始结果”，尚未经过完整的去重、时间轴修正、标点恢复、术语校正和人工审校。

综合评价：**2/5，勉强可用，但必须经过后处理。**

### 对不同用途的影响

| 使用场景 | 可用性 | 说明 |
| --- | --- | --- |
| AI 提取课程主题 | 较高 | 大部分核心内容仍然可以恢复 |
| 生成知识点总结 | 中等偏高 | 需要结合上下文纠正术语和重复 |
| 课程全文检索 | 中等 | 错别字会导致关键词漏检 |
| 学员直接阅读 | 较差 | 重复、零时长、碎句和错词明显影响体验 |
| 精确定位视频内容 | 较差 | 部分时间单元无有效显示时长 |
| 作为课程讲义 | 不合格 | 缺少标点、断句、术语统一和内容整理 |

## 一、SRT 格式与时间轴

### 优点

- 文件整体能够按照标准 SRT 结构解析。
- 未发现明显的非法时间戳格式。
- 大部分字幕顺序与课程时间线一致。
- 只有少量跨字幕时间重叠，说明基础时间排序尚可。

### 主要问题：大量零时长字幕

54,114 个字幕单元中，发现约 **9,878 个结束时间不晚于开始时间的字幕单元**，约占全部字幕的 18.3%。

例如：

```srt
108
00:06:29,100 --> 00:06:29,100
这里就是粒子的数量
```

这种字幕在播放器中可能完全不显示，也可能造成闪烁、跳变或兼容性问题。

部分文件问题尤其严重：

- `04 法则的降神/06 扩散爆炸效果1.srt`：约 66.5% 为零时长单元。
- `02 蚀月斩/10 地面效果1.srt`：约 58.2%。
- `07 命运赦令/05 空中效果2.srt`：约 55.2%。
- `05 少女的终曲/04 弹道效果3.srt`：约 50.1%。

### 过短与过长字幕

- 约 9,947 个字幕单元短于 350 毫秒。
- 约 572 个字幕单元长于 10 秒。

过短字幕很难被人看清；过长字幕则可能覆盖已经说完的内容，造成音画不同步。

### 软件改进建议

1. 所有字幕结束时间必须严格大于开始时间。
2. 建议设置最短显示时间为 500 至 800 毫秒。
3. 相邻字幕之间避免负间隔和无意义重叠。
4. 长字幕应按照语义停顿拆分，而不是机械拉长时间。
5. 导出前自动执行 SRT 合法性检查，并输出异常数量。

## 二、重复字幕问题

### 问题非常突出

检测到约 **22,310 个与上一条文本完全相同的相邻字幕单元**，约占全部字幕的 41.2%。

例如同一句“这里就是粒子的数量”被连续输出十余次；“我们直接在这个曲线上”也出现长时间连续重复。

部分文件的相邻重复比例超过 80%：

- `04 法则的降神/06 扩散爆炸效果1.srt`：约 91.8%。
- `09 穿心波/05 弹道.srt`：约 87.5%。
- `01 陨星/05 拖尾贴图及制作2.srt`：约 85.7%。
- `03 封灵之击/06 戳刺效果1.srt`：约 82.5%。
- `01 陨星/06 开枪效果制作.srt`：约 82.4%。

### 可能原因

从字幕形态判断，软件可能在实时识别时不断输出当前识别窗口的结果，但导出时没有把中间结果合并，只是把每次刷新都保存成了新的字幕单元。

这类重复不能简单理解为老师真的重复说了这么多次。

### 软件改进建议

1. 对相邻完全相同文本进行自动合并。
2. 对“逐步增长”的识别结果进行增量合并，而不是全部保留。
3. 相同文本连续出现时，保留最早开始时间和最晚结束时间。
4. 对短时间内高度相似的字幕进行相似度去重。
5. 去重后重新编号，避免出现大量无意义字幕序号。

## 三、术语识别错误

### 典型错误

字幕对游戏特效专业词汇的识别不稳定，出现了大量可根据上下文确定的误识别。

| 字幕结果 | 推测正确词 | 问题类型 |
| --- | --- | --- |
| 光运 | 光晕 | 同音词误识别 |
| 脱尾、托尾、油尾 | 拖尾 | 专业词不统一 |
| 融解 | 溶解 | 材质术语错误 |
| 法针 | 法阵 | 同音词误识别 |
| 微子 | 粒子 | 专业词误识别 |
| 滴裂 | 地裂 | 同音词误识别 |
| 称底 | 衬底 | 常用表达误识别 |
| 优位 | UV | 英文字母误识别 |
| 蓝粒子 | 软粒子 | 上下文识别错误 |
| 光运材质 | Glow 材质 | 中英文术语混淆 |
| 铁图 | 贴图 | 同音词误识别 |
| 健强 | 渐强 | 同音词误识别 |

仅按一组已知错误进行检索，就发现：

- “光运”约 136 处。
- “托尾”约 64 处。
- “融解”约 47 处。
- “铁图”约 11 处。
- “健强”约 7 处。
- “滴裂”约 6 处。

这还不包含尚未建立错误词表的其他误识别。

### 造成的影响

- 学员可能学习到错误术语。
- 搜索“光晕”“拖尾”“溶解”等正确关键词时会漏掉大量内容。
- AI 总结需要依靠上下文猜测正确词义。
- 英文界面名和插件名容易被翻译成无意义中文。

### 软件改进建议

建立本课程领域的热词表和自动纠错词典，至少覆盖：

- Unity、Particle System、Timeline、Cinemachine。
- Add、Alpha、Glow、Trail、Shader、Material。
- UV、Mesh、Renderer、Vertex Offset、Soft Particle。
- 粒子、材质、贴图、遮罩、溶解、扭曲、拖尾、光晕、法阵、地裂。
- Photoshop、3ds Max 及常见工具名称。

对于英文术语，建议优先保留英文原词，不要强行转成相似发音的中文。

## 四、断句、标点与可读性

### 标点严重不足

约 **94.9% 的字幕文本没有任何常见标点符号**。

这使字幕更像语音片段，而不是经过编辑的句子。复杂解释经常被拆成多条碎句，阅读者需要自行恢复逻辑关系。

### 字幕切分过碎

- 约 11,371 条字幕只有一个字或更短。
- 约 21,109 条字幕不超过四个字。

大量“好”“然后”“这个”“所以呢”等词被单独切成字幕，信息密度低，画面上会频繁跳字。

### 口语填充词

字幕中大量出现：

- “这个”约 13,286 次。
- “好”约 12,678 次。
- “然后”约 8,986 次。
- “我们”约 7,813 次。
- “那么”约 2,497 次。

这些数字受到重复字幕影响，不能直接等同于老师真实口头重复次数，但仍能说明字幕后处理没有去除无意义口语片段。

### 软件改进建议

1. 增加中文自动标点恢复。
2. 按完整语义切分字幕，不要按固定时长机械切分。
3. 合并只有一至四个字的短字幕，除非它具有独立语义。
4. 可提供“原声忠实版”和“阅读优化版”两种导出模式。
5. 阅读优化版可适度去除单独出现的“好、嗯、呃、那么、然后”。
6. 每条字幕建议控制在一至两行，避免单字闪烁和超长句停留。

## 五、内容完整性

### 可取之处

虽然错词和重复较多，但大部分课程主线仍然可以恢复：

- 操作步骤基本连续。
- 参数、工具和制作对象大多能通过上下文辨认。
- 课程章节之间的主题较清晰。
- 可以支持知识点总结、课程检索和主题分类。

### 风险

- 缺少画面时，诸如“这个地方”“上面这个”“刚才那个”很难确定具体对象。
- 个别句子被切断后，单独阅读可能产生相反或不完整的含义。
- 专业术语错误会影响自动摘要和知识库检索。
- `10 九幽龙炎灭` 当前只有 4 个字幕文件，内容覆盖明显不完整；这可能是源文件缺失，不一定是字幕软件的问题。

## 六、字幕软件改进优先级

### P0：必须优先解决

1. 相邻重复字幕合并。
2. 零时长和过短时间轴修正。
3. 实时识别中间结果不要全部写入最终 SRT。
4. 导出前执行格式与时间轴校验。

### P1：显著提升质量

1. 中文标点恢复和语义断句。
2. Unity / 游戏特效专业词表。
3. 中英文术语保留与统一。
4. 短句合并和无意义语气词过滤。

### P2：进一步优化

1. 根据置信度标记疑似错词。
2. 支持用户维护项目级术语表。
3. 输出重复率、零时长率、平均字幕长度等质量报告。
4. 提供“忠实转写”和“精简可读”两种字幕模式。
5. 支持基于上下文的批量纠错，例如自动统一“拖尾、溶解、光晕”。

## 最终评价

当前字幕的核心问题并不是“完全听不懂”，而是**未经整理的实时识别结果被直接导出成了 SRT**。

识别出的主体内容仍然有价值，因此软件基础能力是存在的；但去重、时间轴、断句和专业词汇四个后处理环节明显不足。只要优先解决重复和零时长，再增加专业词表与标点恢复，字幕质量会有非常明显的提升。
